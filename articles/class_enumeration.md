# Choosing the Number of Classes

``` r

library(mixtureEM)
```

Every latent class analysis starts with the same question: *how many
classes?* There is no single decisive statistic, so the standard
practice is to fit a range of solutions and weigh several kinds of
evidence together (Nylund et al., 2007):

1.  **Information criteria** (BIC, SABIC, AIC) — lower is better.
2.  **The bootstrap likelihood ratio test (BLRT)** — a formal test of
    *k* classes against *k* − 1.
3.  **Classification quality** (entropy, average posterior
    probabilities).
4.  **Absolute and local fit** — does the chosen model actually
    reproduce the data?
5.  **Interpretability and class sizes** — a smallest class under 5% of
    the sample, or with fewer than about 25 cases, is one you have to be
    able to defend on substantive grounds, however much it improves the
    BIC (Lee et al., 2023). That is a reporting convention, not a rule;
    mixtureEM applies no minimum and will happily estimate a class of
    three people.

This vignette walks through all five on a classic dataset:
[`poLCA::carcinoma`](https://rdrr.io/pkg/poLCA/man/carcinoma.html), in
which seven pathologists each rated the same 118 biopsy slides for the
presence of carcinoma (Agresti, 2002). The question a latent class model
asks here is: how many *types of slide* are there, given how the raters
agree and disagree?

The chunks below run only if the `poLCA` package is installed
(`install.packages("poLCA")`).

## The bootstrap likelihood ratio test

The BLRT asks the sharper question “does adding one more class fit
significantly better?”, with the null distribution generated by
parametric bootstrap (McLachlan & Peel, 2000). It is slow, because each
replication refits both models; keep `n_reps` modest while exploring. A
test you intend to *report* is a different matter: refit it at
`n_reps = 999`. A bootstrap p-value can only take the values 1/(B + 1),
2/(B + 1), …, so at 50 or 100 draws it cannot separate .04 from .06, and
[`blrt()`](https://pdvalencia.github.io/mixtureEM/reference/blrt.md)
warns when the result lands that close to the line. See
[`vignette("estimation")`](https://pdvalencia.github.io/mixtureEM/articles/estimation.md)
for the power figures behind those numbers.

``` r

set.seed(2)
blrt_23 <- blrt(ratings, k_small = 2, k_large = 3,
                measurement = "binary", n_reps = 50, verbose = FALSE)
blrt_23
#> =========================================================

#> =========================================================
#>   Comparison       : 2 vs 3 classes

#>   LR statistic     : 46.45

```

The 2-vs-3 test rejects (a third class is needed); the 3-vs-4 test does
not, agreeing with BIC.

### Which entropy is being reported

Relative entropy is an absolute entropy expressed on a 0-1 scale, and
there is more than one convention for the denominator that puts it
there. mixtureEM divides by $`n \log K`$, the entropy of a uniform
distribution over the $`K`$ classes — the largest value the absolute
entropy could take. Some other implementations divide instead by
$`n H(\hat\pi)`$, the entropy of the *estimated* class sizes. Both
appear in the literature and neither is wrong, but they do not give the
same number, so an entropy quoted from elsewhere is not always
comparable with the one printed here.

Because $`H(\hat\pi) \le \log K`$ always, with equality only when the
classes come out exactly equal in size, the figure reported here is
always the higher of the two. The gap is small for balanced solutions
and grows as the class sizes become uneven. To convert:

``` math
R^2_{\text{other}} = 1 - (1 - R^2_{\text{here}}) \frac{\log K}{H(\hat\pi)},
\qquad H(\pi) = -\sum_k \pi_k \log \pi_k
```

Either way, entropy describes how cleanly a solution separates cases; it
is not evidence for how many classes there are. A model can separate two
classes beautifully and still be the wrong model.
